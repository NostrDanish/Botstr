# Security Audit — Botstr — 2026-10-20

## Summary

Botstr is a "deploy Nostr bots in minutes" platform: a Vite/React dashboard plus a Cloudflare Worker (`worker.ts`) fronting one Durable Object per bot. Bot nsec keys are sealed with AES-256-GCM (key = SHA-256 of `BOTSTR_SECRET`) inside the DO, the worker refuses to run without `BOTSTR_SECRET`, identity rotation happens inside the node, and the inbound relay gateway (`src/lib/gateway.ts`) verifies signatures, enforces mailbox-mode restrictions, and rate-limits. However, the **entire management API has no authentication or authorization of any kind** — including an endpoint that returns any bot's decrypted private key. Safe only if the deployment is unreachable by untrusted parties, which nothing enforces.

Findings: 1 Critical / 1 High / 2 Medium / 1 Low

## Findings

| ID | Severity | File/Area | Issue | Recommended fix |
|----|----------|-----------|-------|-----------------|
| BOT-01 | CRITICAL | `worker.ts` — `GET/POST /api/bots/:id/export` (+ DO `/export`) | Unauthenticated key exfiltration: anyone who can reach the deployment can POST `/api/bots/<id>/export` and receive the bot's **plaintext nsecHex plus all decrypted per-bot secrets**. Bot IDs are enumerable-ish (16-hex) and `GET /api/bots` (also unauthenticated) lists every bot with its id and pubkey. | Add an owner-auth layer on ALL `/api/*` routes (e.g. shared bearer secret, Cloudflare Access, or NIP-98 against an owner pubkey allowlist) before any non-localhost deployment. At minimum, gate `/export`, `/provision`, `/rotate`, DELETE, and `/files` behind auth. |
| BOT-02 | HIGH | `worker.ts` — whole `/api/bots` surface | No authZ/authN anywhere: strangers can create bots (POST with their own nsecHex → spam/resource abuse on your Workers plan), stop/restart/delete any bot, read logs/events, and upload/download per-node files (`/api/bots/:id/files`). | Same fix as BOT-01 — one auth middleware in the API worker covers all of it. |
| BOT-03 | MEDIUM | `worker.ts` `sealKey()/openKey()` | At-rest encryption key is raw `SHA-256(BOTSTR_SECRET)` with no KDF/salt — security rests entirely on the secret's entropy; docs don't state a minimum. Also, initial provisioning sends `nsecHex` from the browser to the worker over TLS (rotation correctly avoids this, first provision does not). | Document "generate with `openssl rand -hex 32`" or derive via HKDF; prefer generating the first identity inside the node (like `/rotate`) instead of browser→worker transfer. |
| BOT-04 | MEDIUM | `Dockerfile` | Self-hosted container runs `wrangler dev --ip 0.0.0.0` (miniflare) — a dev server exposed on all interfaces, with the same unauthenticated API (BOT-01/02) and `BOTSTR_SECRET` written to `.dev.vars` on disk. Fine on a trusted box, dangerous if port 8787 is exposed. | Bind to localhost by default; document that exposing 8787 without a reverse-proxy auth layer exposes all bot keys. |
| BOT-05 | LOW | Repo hygiene | No SECURITY.md. Otherwise good: `.gitignore` covers env, `wrangler.jsonc` uses `REPLACE_WITH_YOUR_D1_DATABASE_ID` placeholder, secrets via `wrangler secret put`. | Add SECURITY.md with a "never deploy the API unauthenticated" warning. |

## Secrets Check

- Reviewed: `worker.ts`, `wrangler.jsonc`, `Dockerfile`, `docker-compose.yaml`, `package.json`, `migrations/0001_init.sql`, `src/lib/{gateway,vault,identity}.ts`.
- Secret scanning (GHAS) unavailable; code-search indexing incomplete → files read directly.
- **No committed secrets.** All sensitive material is designed as runtime secrets (`BOTSTR_SECRET`, provisioned nsecHex) and sealed at rest (AES-256-GCM in DO storage; AES-GCM with a non-extractable device key in the browser vault). Placeholders only in configs.

## Recommended Actions

1. [CRITICAL] Put owner authentication in front of every `/api/*` route; until then treat any deployed instance as leaking all bot keys (BOT-01/02).
2. [MEDIUM] Strengthen/document `BOTSTR_SECRET` entropy; generate first identity in-node (BOT-03).
3. [MEDIUM] Bind the Docker dev runtime to localhost; warn about exposure (BOT-04).
4. [LOW] Add SECURITY.md (BOT-05).
