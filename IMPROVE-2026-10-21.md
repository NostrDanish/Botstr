# Improvement Deep-Dive — Botstr — 2026-10-21

Scope: main. Sources read: `worker.ts` (full API worker + BotRunner DO), `wrangler.jsonc`, `package.json`, `.github/workflows/deploy.yml`, `README.md`, directory listings of `src/lib`, `tests`, `docs`.

## Top recommendations (ranked, with effort S/M/L)

1. **Owner-auth middleware for `/api/*` — the platform's missing gate (M).** Today every API route is unauthenticated: anyone on the internet can `POST /api/bots` (provision bots on your paid CF account), `DELETE /api/bots/:id`, and — worst — `POST /api/bots/:id/export`, which returns the bot's **plaintext nsecHex and decrypted secrets**. Design:
   - Add `OWNER_PUBKEY` (hex) as a var + `BOTSTR_OWNER_TOKEN` as a secret.
   - Middleware runs before routing for all `/api/*` except a public allowlist: `GET /api/health`, `GET /nodes/:id` (public discovery doc), `/nodes/:id/relay` (the node's public inbound relay — must stay open when gateway mode != private).
   - Primary mechanism: **NIP-98 HTTP auth** (kind 27235, `Authorization: Nostr <base64>`): verify signature, `pubkey == OWNER_PUBKEY`, `u` tag matches request URL, `method` tag matches, `created_at` within ±60 s, `payload` tag hash when body present. Nostr-native, no password to leak, works with any signer.
   - Fallback mechanism for CLI/scripts: static `Authorization: Bearer $BOTSTR_OWNER_TOKEN`.
   - Fail closed (401 JSON), log auth failures, and apply the same check to the files proxy (`/api/bots/:id/files/*`).
   - The DO itself is only reachable through the worker, so one choke point suffices — but keep the worker→DO internal routes (`/provision`, `/export`, `/rotate`) unexposed by never forwarding arbitrary paths.
2. **Wire `npm test` into CI (S).** `tests/` has gateway/giftwrap/manifest/templates vitest suites; `.github/workflows/deploy.yml` only builds and deploys to Pages — tests never run in CI. Add a `test` job (`npm ci && npm run test`) gating deploy, and fix the peer-dep conflicts so `--legacy-peer-deps` isn't needed.
3. **Strengthen at-rest key sealing (S).** `sealKey` uses raw `SHA-256(BOTSTR_SECRET)` as the AES-GCM key. Use HKDF-SHA-256 (info="botstr-node-key") instead, and prefix sealed blobs with a key version (`v1:`) so `BOTSTR_SECRET` rotation is possible without bricking existing nodes.

## Quick wins (code/config)

- **`/export` returns plaintext keys over the API.** Even with owner auth, require a separate confirmation scope (e.g. NIP-98 with a `t"export"` tag) and rate-limit it; log every export to D1 audit table.
- **Stale platform constraint**: `worker.ts` rejects >6 relays per node citing "6 simultaneous outgoing connections per invocation". Cloudflare relaxed this in Apr 2026 — only connections *waiting for response headers* count; established outbound WebSockets don't consume the 6 slots. Re-test and raise the cap (still keep *some* cap for DO memory: 128 MB isolate, each relay socket + ring buffers cost real heap).
- `PUT /api/bots/:id/files/*` has no content-type/size guard at the worker layer (DO enforces quota, but add an early 413 at the worker to avoid burning DO requests).
- `compatibility_date: 2026-08-25` is fresh; keep it pinned and review quarterly.
- `wrangler.jsonc` ships `database_id: REPLACE_WITH_YOUR_D1_DATABASE_ID` — good for a template; add a `deploy check` script that fails fast if placeholders remain.
